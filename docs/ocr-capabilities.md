# OCR 能力与验收边界

2026-11-22，v0.6.0a1。全文、文档定位及实例识别已接通实际多模态模型；未引入其他 OCR 引擎或下载权重。这里只记录实现状态，准确率取决于配置的模型和业务数据，合成样本通过不等于商用精度验收。

新增通用表格、上下文定位、行列锚点、小角度纠偏和字段来源坐标，详见 [使用与边界](tables-and-localization.md)。

## 当前执行链

- 全文：图片/PDF → EXIF 归一化、渲染/缩放 → 每页多模态 OCR → 文本/Markdown、文字块与来源坐标 → 检查点和导出。
- 多文档：页面多模态定位/分类 → 校验坐标 → 每实例真实裁剪 → 同模型全文 OCR 或固定版本业务 Schema 路由 → 每实例检查点 → 原页区域与裁剪图展示。
- 业务字段：固定 Schema、系统/用户提示词与字典 enum → 图像模型 → JSON 解析和字段校验 → 标准答案叶子字段评测。

`vision.py` 是可独立调用的模型契约与几何处理，`recognition.py` 执行持久化流水线，`detection.py` 导出正在执行的多模态定位函数及可扩展协议。页面、HTTP API、CLI 和 Python 库均有实际入口，见 [多模态使用指南](multimodal-ocr.md)。

| 能力 | 当前实现与边界 |
|---|---|
| 全文 OCR | 已实现；无需定义字段，输出原语言文本或 Markdown、模型文字块、原始响应和实际 usage |
| 来源坐标与位置叠加 | 已实现模型位置校验、旋转/裁剪逆映射、原图像素/PDF points 映射；位置由模型报告且未核验，缺失留空 |
| 置信度 | 不编造；模型无可靠校准分数，统一 null |
| 同图多文档 | 已实现同模型定位、真实裁剪、分类、独立实例 ID 与类别路由；不保证遮挡/重叠目标均能检出 |
| PDF/图片与页范围 | 已实现；全文/多文档逐页，业务提取可联合最多 8 页；不复用 PDF 文本层 |
| 方向处理 | EXIF、手动旋转、可选小角度投影纠偏、仿射四角逆映射；无自动 90° 内容方向检测或透视矫正 |
| 业务 KV、分组与明细表 | 已实现 Schema/提示词、不可变版本、字典快照和校验；业务数组不等于原表网格 |
| 导出 | JSON、TXT、Markdown；通用表格表头/表体/合并跨度与 CSV/HTML；无 Excel、可搜索 PDF 或原版像素排版复刻 |
| 恢复与失败 | 逐页/逐实例检查点、实例部分失败、幂等提交、取消和显式重跑；在途调用不是恰好一次 |
| 评测 | 原业务 JSON 标准答案精确比较；尚无完整 CER/WER、检测 IoU、表格结构指标或代表性公开基准 |
| 多页业务合并 | 无自动续表、跨文件分组、正反面配对、去重和冲突裁决 |
| 人工复核 | 可回看来源与裁剪，不包含修改结果、审核状态及回写流程 |
| 自部署/在线 | 已实现社区与多租户入口、鉴权、隔离、额度；单进程 Alpha，无支付/HA/SSO |

## 开源价值

用户不需要先搭建管理系统或定义业务字段就能运行 OCR。识别核心可以通过库/CLI 使用，HTTP 提供有界上传与持久化任务，页面提供来源核验和业务配置。类别路由把独立文档实例与版本化提取结构连接，错误、原始响应和真实用量保留，便于替换模型和复现问题。

全部视觉任务统一多模态，但仍拆开定位、真实裁剪、实例识别与校验，分别保存证据；没有用一次大提示词要求模型输出全部内容后伪造裁剪或位置。旧 ocr-app-v7 的专用模型、权重、客户逻辑和专项后处理没有整体复制或迁移。

## 下一阶段

1. 获授权的代表性公开数据集：分别评测文字、定位、业务字段、耗时和实际用量，记录模型/提示词/预处理版本。
2. 密集小字高分辨率处理、倾斜/透视输入、可验证表格结构与单字段来源证据。
3. 原始结果与人工纠错分开保存，纠错转标准答案；跨页续表、正反面配对和冲突规则。
4. 隔离解析进程、保留期与删除、独立 worker/对象存储/数据库，容量与安全验收。

这些是未交付的研发方向。开源维护提供通用主链路和可复现样例；定制可围绕授权业务场景的效果优化、长尾票种、系统连接和部署支持展开，不能以模板存在宣称专项识别精度。
