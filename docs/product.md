2026-11-22，v0.4：已实现全文多模态 OCR、多文档定位/裁剪/实例路由，以及结构化提取/评测。全部视觉任务使用所选多模态模型；旧 ocr-app-v7 的专用模型与后处理未整体迁入。实际边界见 [能力审计](ocr-capabilities.md)。

全文和多文档无需定义字段：选择模型 → 上传文档 → 逐页 OCR，或先定位/裁剪再逐实例识别 → 查看文本/裁剪/来源坐标 → 导出。多文档可选固定版本的类别字段路由；定位与实例分别检查点保存。用法、坐标来源和模型调用成本见 [多模态指南](multimodal-ocr.md)。

当前实现围绕一个完整流程：建立应用 → 编辑结构/提示词 → 保存版本 → 上传文件 → 选择模型和页范围 → 提交持久化任务 → 查看 JSON/校验/来源页 → 添加标准答案 → 运行评测 → 对比版本。

页面包括：提取工作台、字段与表格、提示词版本、字典管理、数据集与评测、任务记录、模型接入；在线模式增加团队与用量、平台管理。草稿在页面内编辑，切换应用/版本时会提示未保存状态；执行前自动保存有改动的草稿。已保存版本不覆盖。

表格通过 `array.items.properties` 定义表头列，表体是模型提取的记录数组。文档级 KV 与表格并列；需要多个分组时，在分组数组中配置自己的 KV 与明细数组。页面可编辑对象数组；字段可选值可在页面手工编辑或从字典指定版本复制，非对象数组仍使用 JSON Schema 导入。编辑一个字段的类型时会清除该字段原有的子结构/enum；可切回旧版本恢复。

PDF 的源文件、页面和模型处理单元分开记录。联合模式每个文件输出一个 object，逐页模式每页一个 object。结果中的 `pages` 只表示实际输入的页码集合，默认不声称每个字段精确来自其中哪一页；开启精细定位后，另以 field_locations 返回逐页模型位置和无法定位的记录，业务 JSON 不变。模型没有返回坐标/置信度时，工作台不编造。

评测采用严格叶子字段比较。字符串不自动去空格、改大小写或做金额格式转换；JSON 数值 1 与 1.0 相等，布尔值 true 与 1 不相等。数组按位置对齐，不做业务主键配对；空数组/对象作为一个叶子值。缺失、null 和空字符串互不等价。额外输出字段单列，但不加入标准答案分母。Schema 校验状态与字段精确匹配率分开观察：部分正确但整体校验失败的输出仍可以获得部分字段分数。没有标准答案不显示准确率。

评测运行固定模板、模型配置与标准答案快照；后续向数据集追加样本不改变历史运行。比较记录时应检查样本快照一致性，首版不提供显著性检验或可替代人工验收的业务结论。

## v0.3 已补齐

- 双模式部署：本地令牌工作空间；在线账户、独立团队库和文件、实时角色校验。
- 在线成员邀请、接口密钥、会话撤销、模型地址允许列表和密钥加密、团队用量/额度和操作审计。

- 直接打开 HTML 时提供服务启动引导；正常 HTTP 工作流不依赖前端构建。
- 源码包校验与解压启动检查；CI 增加双系统验证、依赖检查和非 root 容器启动/重启持久化检查。CI 尚未在公开仓库实跑。

## 后续优先级

1. 使用获授权的真实模型和公开样本验证至少一个完整部署组合，记录字段指标、时延与资源成本。
2. 评测多模态定位在遮挡、重叠、小字、方向和长尾类型上的表现，增加高分辨率处理及人工纠错。
3. 跨页续表、文档分类/拆分、跨文件业务归并、单字段来源证据和标注工具。
4. 细粒度评测、按业务主键对齐明细、数据集编辑删除、连接配置轮换、数据保留和清理策略。
5. PostgreSQL/对象存储/独立 worker、细分资源权限、SSO、实际支付订阅和多实例运维。

当前不包含自动方向/透视矫正、支付扣费、队列多实例、扫描仪/PPT/Office 转换、模型训练、人工审核流或业务系统回写。文档定位已通过多模态服务实现；位置未经人工核验，置信度留空，不代表专项识别精度。
